# AGENTS.md

This file gives coding agents project context for `SAP-Calculator`.

## Project Overview
- App: Battle calculator for Super Auto Pets.
- Stack: Angular 21 + TypeScript, Vitest for main tests, optional Node replay server, optional headless simulation CLI.
- Use Node 22.12+ for development (Angular 21 toolchain).

## Repo Map
- `src/app/domain`: Lightweight board-editor models and simulation types.
- `sap-battle-engine` dependency: All battle mechanics, abilities, and canonical content catalogs.
- `src/app/integrations`: Engine adapter, editor catalogs, replay services, analysis, and log presentation.
- `src/app/runtime`: App state, persistence, and runtime utilities.
- `src/app/ui`: Angular shell and feature UI components.
- `tests`: Vitest integration/regression specs and engine-boundary meta checks.
- `simulation`: Headless simulation library + CLI bundle.
- `server`: Optional replay API proxy backend.
- `scripts`: Generation/debug/replay/evolution utilities.
- `docs`: Architecture/process references.

## First Commands
- Install: `npm install --legacy-peer-deps`
- Configure env: `copy .env.example .env` (Windows) or `cp .env.example .env`
- Start UI: `npm start`
- Start replay server: `npm run start:server`
- Build: `npm run build`

## Testing Commands
- Full Vitest: `npm run test:vitest`
- Specs only: `npm run test:vitest:specs`
- Meta checks: `npm run test:vitest:meta`
- Legacy Angular/Karma: `npm test`

## Agent Workflow Expectations
- Keep layer boundaries intact (editor models -> integrations/runtime -> UI; battle mechanics stay in the dependency).
- Keep root clean; place temporary files under `tmp/` (see `docs/ROOT_LAYOUT.md`).
- Prefer focused edits and targeted tests for touched areas.
- Do not use TypeScript `any`; it violates lint rules (`@typescript-eslint/no-explicit-any`).
- Do not manually edit generated outputs in `dist/` or dependencies in `node_modules/`.
- Tracked simulation bundles in `simulation/dist/` are an exception when regenerated by `npm run build` or `npm run bundle-simulation`; include their expected changes with the source change that produced them.

## Source of Truth (Content Data)
- `sap-battle-engine` owns canonical pets, toys, food, perks, and battle implementations.
- `src/app/runtime/content-catalogs.ts` provides metadata copies for form/parser consumers.
- Do not reintroduce local combat classes, ability queues, registries, or copies of canonical content JSON.
- Keep equipment editor metadata aligned with the pinned engine catalogs.
- Update mechanics in the engine repository, bump its pinned Git revision here, update editor metadata when needed, and run specs/meta checks plus the production build.
- Keep dependency provenance documented in `docs/BATTLE_ENGINE.md`.

## Replay + Simulation Notes
- UI replay calls proxy through `/api` using `config/proxy.conf.js`.
- `REPLAY_API_TARGET` in `.env` controls replay backend target.
- Headless simulation bundle/CLI is built by `npm run bundle-simulation`.
- Replay docs:
  - `docs/DEPLOY_REPLAY.md`
  - `docs/REPLAY_BOT_PARSER.md`
  - `docs/REPLAY_JSON_GENERATOR.md`

## Definition of Done for Agent Changes
- Code compiles for touched areas.
- Relevant tests pass for the scope changed.
- New behavior uses the dependency API and keeps editor metadata aligned.
- Notes for any skipped verification are explicitly stated.
